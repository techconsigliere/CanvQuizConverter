      How to write the quiz

      Open a blank Word document and type it like this:

      1. Chris' favorite color is:
*a. Black
b. Blue
c. Red
d. Turquoise

2. Canvas quizzes can be written in Word.
*a. True
b. False
      • Start each question with a number and a period: 1. Question text. A question can run onto a second line.
      • Start each answer choice with a letter and a period: a. Choice text. Upper or lowercase both work, and so do 1) and a).
      • Put an asterisk before the letter of the correct answer: *b. Choice text.
      • Mark more than one correct answer and the question becomes multiple-answer. The preview flags it so you can confirm that's what you meant.
      • If Word turns your numbers and letters into an automatic list, that's fine. The converter reads Word's numbering too. In that case, put the asterisk at the start of the choice text instead.

      No styles, tables, or special formatting needed. Blank lines between questions are fine.

      Importing it into Canvas

      1. In your Canvas course, open Settings from the course menu.
      2. On the right, click Import Course Content.
      3. For Content Type, choose QTI .zip file, then choose the file you downloaded.
      4. Leave All content selected and click Import.
      5. When the import shows Completed, open Quizzes. Your quiz is there, unpublished, with its questions also saved in a question bank.
      Check it before students do

      Open the quiz in Canvas, preview it, and set the points, time limit, and availability dates before you publish. The converter brings in the questions and the right answers; everything else is set in Canvas.

      What it handles, and what it doesn't

      What it makes

      • Multiple choice questions
      • True/false questions, written as two choices
      • Multiple-answer questions, when more than one choice is marked
      • A Classic Quiz plus a question bank, both in your course

      What it leaves to Canvas

      • Essay, matching, fill-in-the-blank, and numeric questions
      • Images, bold, and other formatting in question text
      • Questions written inside a Word table
      • Points other than one per question, and quiz settings

      Privacy and trust

      An answer key is exactly the kind of file that shouldn't wander. Here's what actually happens to it.

      • Nothing is uploaded. Your browser reads the Word file and builds the Canvas file on this page. There's no server behind this site to send it to, just the page itself, hosted on GitHub Pages.
      • The page can't phone home. Its security policy forbids it from making network requests to anyone, including me. You can check: open your browser's developer tools, switch to the Network tab, and convert a quiz. You'll see the page load its own files and nothing after that.
      • No account, no Canvas access, no tracking. It never connects to Canvas. You do the import yourself, inside Canvas, with your own permissions. No analytics, no cookies, and no third-party code at all.
      • Nothing is saved. Close the tab and the quiz is gone. The only copy it makes is the file you download.

      The whole converter is one readable file, canvquiz.js, using only what's built into your browser.

      Beta software from one person

      I'm a Canvas administrator in higher education, and I wrote this because faculty shouldn't have to build a quiz one web form at a time. Your institution hasn't reviewed it. If that matters where you work, ask your own IT or Canvas team before you use it. I'd rather you ask than assume.

      Prefer to run it offline?

      The original version is a small Python program you run on your own computer. It does the same conversion without a browser page. Setup instructions are in the README on GitHub.

      When it gets something wrong

      If the preview doesn't match your document in a way that matters, open an issue and tell me what went wrong and which program made the file. Please don't attach a real quiz; a made-up question in the same format is perfect.

      Page look out of date? GitHub can keep showing an older copy for a few minutes after an update. Hard-refresh with Ctrl + Shift + R, or Cmd + Shift + R on a Mac, and check that the version near the top matches the latest one on GitHub.
